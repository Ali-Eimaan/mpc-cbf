# Media

Animated assets for the root `README.md`. Each is produced by a notebook cell, never by
hand-recording a screen — a regenerable figure is a figure a reviewer can trust.

## Inventory

All three are present as of v1.0.0, and each is regenerated by executing its notebook.

| File | Size | Produced by | Shows |
|---|---|---|---|
| `obstacle_avoidance.gif` | 0.42 MB | `reproduction/zeng_acc2021/reproduce_acc2021.ipynb` §2 | 2-D obstacle avoidance at γ ∈ {0.1, 0.2, 0.3, 1.0}, with `h(x)` for every γ alongside |
| `cbfqp_vs_mpccbf_side_by_side.gif` | 0.24 MB | `analysis/cbfqp_vs_mpccbf_comparison.ipynb` (final cell) | CBF-QP colliding with a fast obstacle next to MPC-CBF avoiding it, same scenario, same seed |
| `tube_robustness.gif` | 0.60 MB | `analysis/disturbance_robustness_sweep.ipynb` §2 | worst-case disturbance in `W`: the untightened CBF clips the obstacle (`min h = −0.0805`), tube-MPC-CBF holds the margin (`min h = +0.0369`) |

The `obstacle_avoidance` animation reuses the Fig. 4(d) rollouts computed earlier in the same
notebook — no extra solves — so the GIF and the static figure cannot drift apart. The
`tube_robustness` animation runs its own instrumented worst-case rollout at the design magnitude,
recording `x`, the nominal `z` and `h` at every step, and draws Ω's position projection around the
nominal state so that what the RPI certificate actually bounds is visible rather than asserted.

## Regeneration

```bash
jupyter nbconvert --to notebook --execute reproduction/zeng_acc2021/reproduce_acc2021.ipynb
```

```bash
jupyter nbconvert --to notebook --execute analysis/cbfqp_vs_mpccbf_comparison.ipynb
```

```bash
jupyter nbconvert --to notebook --execute analysis/disturbance_robustness_sweep.ipynb
```

Each cell writes the GIF, prints its size and duration, and asserts the constraints below, so a
regeneration that breaks one of them fails the notebook rather than silently shipping a bad asset.

## Constraints

≤ 8 MB each (GitHub renders them inline; larger files stall the README), ≤ 8 s, ≥ 15 fps, and every
frame must carry the current `h(x)` value so the safety claim is legible from the GIF alone.
