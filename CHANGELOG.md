# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project uses
[semantic versioning](https://semver.org/spec/v2.0.0.html).

## [1.0.0] — 2026-08-15

First release. Everything below was verified in a clean `ros:lyrical-ros-base`
container (Ubuntu 26.04, ROS 2 Lyrical Luth, GCC 15.2, CMake 4.2, acados v0.6.0
with HPIPM): 97 tests with 0 failures, both reproduction notebooks executing
end-to-end, and all three derivations compiling.

### Added

- **MPC-CBF solver** (`MpcCbfSolver`) — discrete-time control barrier function
  constraints imposed along the prediction horizon, on top of acados/HPIPM.
  Three variants selected by configuration: fixed decay (ACC 2021), relaxed
  decay with `ω_k` as a decision variable (CDC 2021), and a distance-only
  MPC-DC baseline.
- **Tube MPC-CBF solver** (`TubeMpcCbfSolver`) — robust safety under bounded
  disturbance via an offline RPI set, an ancillary feedback law, and
  support-function tightening of both barrier rows.
- **Convex set machinery** (`disturbance_sets.hpp`) — H-representation
  polytopes, zonotopes, Minkowski sums, Pontryagin differences, and a Raković
  outer approximation of the minimal RPI set, with a dense simplex LP backend.
- **Code generation** (`codegen/`) — one CasADi definition of the four plants,
  the barrier and the DCBF condition, shared by both acados generators, the
  test suite and every notebook.
- **ROS 2 node** (`mpc_cbf_node`) — fixed-rate controller with live-tunable
  parameters, four fallback policies on infeasibility, and per-stage barrier
  diagnostics; four launch files with headless simulators.
- **Test suite** — 97 tests: gtest for the solvers and set machinery, pytest
  for the feasibility sweep, and a C++/Python parity harness.
- **Reproductions** — both source papers reproduced figure by figure, with
  matched values, tolerances and an explicit deviations list in
  `reproduction/REPRODUCTION_REPORT.md`.
- **Analysis** — CBF-QP vs MPC-CBF over 100 seeded scenarios, feasibility loss
  and recovery, and a disturbance robustness sweep.
- **Documentation** — math summary, three LaTeX derivations, annotated prior
  art, and a Limitations section stating what the repository does not prove.
- **Media** — three animations, each generated by a notebook cell that asserts
  its own size, duration and frame-rate budget: the γ sweep from the ACC
  reproduction, the CBF-QP/MPC-CBF comparison, and the tube holding its margin
  under worst-case disturbance where the untightened CBF clips the obstacle.

### Fixed

Found while verifying this release in the container; each had been latent.

- `cpp_solve_cli` emitted an unquoted status token (`"status": SUCCESS`),
  making its output invalid JSON. The C++/Python parity check therefore failed
  at the parse step and had never actually compared a control input.
- `cpp_solve_cli` let acados' stdout diagnostics into its own JSON stream,
  corrupting it on exactly the hard states the parity check exists to compare.
  The solve is now wrapped in a stdout guard.
- `cpp_solve_cli` reused one solver across all requests, so each solve was
  warm-started from the previous, unrelated state — the documented route to an
  `ACADOS_MINSTEP` stall. Each request now coasts from `u = 0`, and the parity
  test's Python side does the same, so the two front-ends compare the same
  problem. They now agree to 4.33e-15 against a 1e-6 bound.
- `docs/derivations/discrete_time_cbf.tex` used an undefined `remark`
  environment and did not compile.

### Changed

- The acados build in CI no longer enables qpOASES or OSQP. Both are unused —
  the generated solvers request `PARTIAL_CONDENSING_HPIPM` exclusively — and
  each broke the build on the target container: the vendored OSQP declares
  `cmake_minimum_required(3.2)`, which CMake 4 rejects, and the vendored
  qpOASES has an incompatible-pointer-type error that GCC 15 treats as fatal.

### Known limitations

Stated in full in the README and `docs/README_math.md` §6. In brief: no
recursive-feasibility certificate; safety is conditional on per-step
feasibility; the RPI certificate is exact only for the linear model; obstacle
prediction error and state-estimation error are outside the tube; obstacles
beyond the nearest eight are dropped; multi-agent coupling is out of scope.
