## §1. The mathematics you are implementing

Implement from this section; use the papers to check yourself, not the other way round.

### §1.1 Discrete-time CBF

System `x_{k+1} = f(x_k, u_k)`, safe set `C = { x : h(x) ≥ 0 }`.

`h` is a **discrete-time CBF** if there is a class-K function `α` with `α(r) ≤ r` such that

```
sup_{u ∈ U} [ h(f(x,u)) − h(x) ] ≥ − α(h(x))     for all x ∈ C.
```

With the linear choice `α(r) = γ r`, `γ ∈ (0, 1]`:

```
h(x_{k+1}) − h(x_k) ≥ − γ h(x_k)      ⟺      h(x_{k+1}) ≥ (1 − γ) h(x_k).          (DCBF)
```

**Invariance.** If `h(x_k) ≥ 0` and (DCBF) holds with `γ ≤ 1`, then `h(x_{k+1}) ≥ (1−γ) h(x_k) ≥ 0`.
Induction gives forward invariance of `C`. This two-line argument is the entire safety guarantee — every
validation check in the code exists to protect one of its hypotheses.

**Consequences you must enforce in code:**

| Hypothesis | Enforced where |
|---|---|
| `γ ∈ (0, 1]` | `MpcCbfSolver::initialize()`, `setGamma()`, ROS parameter range |
| `h(x_0) ≥ 0` | explicit `h(x_k) ≥ 0` row in the OCP, so an unsafe start reports infeasible |
| `ω_k γ ≤ 1` | `initialize()` rejects `omega_max * gamma > 1` |

### §1.2 The MPC-CBF optimal control problem

At time `t`, with horizon `N` and CBF horizon `N_CBF ≤ N`:

```
min  Σ_{k=0}^{N-1} [ ‖x_{k|t} − x_ref_k‖²_Q + ‖u_{k|t}‖²_R ] + ‖x_{N|t} − x_ref_N‖²_Qf
s.t. x_{k+1|t} = f(x_{k|t}, u_{k|t}),                       k = 0..N−1
     x_{0|t}   = x_t
     x_{k|t} ∈ X,  u_{k|t} ∈ U
     h_j(x_{k|t}) ≥ 0,                                      k = 0..N,   j = 1..n_obs
     h_j(x_{k+1|t}) − h_j(x_{k|t}) ≥ − γ h_j(x_{k|t}),      k = 0..N_CBF−1
```

Both barrier rows are required. The DCBF row alone preserves safety only *from* a safe state; the plain
`h ≥ 0` row is what makes an already-unsafe state report infeasible instead of tracking a negative
barrier value downward.

### §1.3 Relaxed decay rate (CDC 2021)

Replace the fixed `γ` by a per-stage, per-obstacle decision variable:

```
h_j(x_{k+1|t}) − h_j(x_{k|t}) ≥ − ω_{k,j} γ h_j(x_{k|t}),      ω_{k,j} ∈ [ω_min, ω_max]
```

with `p_ω Σ (ω_{k,j} − 1)²` added to the stage cost. `ω = 1` recovers the fixed-decay problem; the
optimiser pays only where relaxation is needed.

**Safety condition:** `h(x_{k+1}) ≥ (1 − ω γ) h(x_k) ≥ 0` requires `ω γ ≤ 1`. Therefore
`omega_max * gamma ≤ 1` is a *hard* configuration check, not a warning. With the YAML defaults
(`gamma 0.3`, `omega_max 3.0`) the product is exactly 1.0 — that is deliberate, and it is the boundary
case your validation must accept rather than reject. Use `<= 1.0 + 1e-9`.

### §1.4 Feasibility — read this before writing the feasibility tests

DCBF constraints inside an MPC **do not** confer recursive feasibility. Feasibility at time `t` does not
imply feasibility at `t+1`. The standard sufficient conditions (a terminal control-invariant set contained
in `C`, or a horizon long enough to reach one) are **not** implemented here.

Consequences:
- `test_recursive_feasibility.py` **measures** the feasible set; it does not assert a theorem.
- Any comment, docstring or notebook claiming a recursive-feasibility guarantee is a bug. Fix it.
- The infeasibility-recovery behaviour (§6.4) is a mitigation, not a proof.

### §1.5 Tube MPC-CBF

Plant `x_{k+1} = A x_k + B u_k + w_k`, `w_k ∈ W` compact convex with `0 ∈ W`.

```
nominal:    z_{k+1} = A z_k + B v_k
control:    u_k = v_k + K (x_k − z_k)
error:      e_{k+1} = (A + B K) e_k + w_k,      e_k ∈ Ω  for all k  if  e_0 ∈ Ω
RPI:        A_cl Ω ⊕ W ⊆ Ω,     A_cl = A + B K  Schur
tighten:    X ⊖ Ω,   U ⊖ K Ω
```

**Barrier tightening.** With `h_j(x) = ‖P x − p_j‖² − r_j²` (`P` the position selector),

```
h_j(z + e) = h_j(z) + 2 (P z − p_j)ᵀ P e + ‖P e‖²
```

so, since `‖P e‖² ≥ 0`,

```
min_{e ∈ Ω} h_j(z + e)  ≥  h_j(z) − h_Ω( −∇h_j(z) ),        ∇h_j(z) = 2 Pᵀ (P z − p_j)
```

Define the margin `c_j(z) = h_Ω(−∇h_j(z))` — the support function of `Ω` in the direction of steepest
barrier decrease. Then `h_j(z) − c_j(z) ≥ 0 ⟹ h_j(x) ≥ 0` for the true state. The Lipschitz alternative
`c_j = L_h · max{‖e‖ : e ∈ Ω}` is also sound and always at least as conservative.

The robust rows in the nominal problem:

```
h_j(z_k) − c_{j,k} ≥ 0
h_j(z_{k+1}) − h_j(z_k) ≥ − γ ( h_j(z_k) − c_{j,k} )
```

### §2.2 `codegen/models.py` — implement first

Single source of truth for dynamics and barriers. Four models:

| `ModelType` (C++) | registry key | nx | state | nu | input | position indices |
|---|---|---|---|---|---|---|
| `kDoubleIntegrator2D` | `double_integrator_2d` | 4 | `[px, py, vx, vy]` | 2 | `[ax, ay]` | (0, 1) |
| `kUnicycle2D` | `unicycle_2d` | 3 | `[px, py, θ]` | 2 | `[v, ω]` | (0, 1) |
| `kBicycleKinematic` | `bicycle_kinematic` | 4 | `[px, py, θ, v]` | 2 | `[a, δ]` | (0, 1) |
| `kQuadrotorPlanar` | `quadrotor_planar` | 6 | `[px, pz, vx, vz, φ, φ̇]` | 2 | `[T, τ]` | (0, 1) |

Continuous dynamics:

```
double_integrator_2d:  ṗ = v,                       v̇ = u
unicycle_2d:           ṗ = [v cos θ, v sin θ],      θ̇ = ω
bicycle_kinematic:     ṗ = [v cos θ, v sin θ],      θ̇ = v tan(δ)/L,   v̇ = a
quadrotor_planar:      ṗ = [vx, vz],                v̇ = [−T sin φ / m, T cos φ / m − g],   φ̈ = τ / I
```

`discretise()` — RK4 by default; for `double_integrator_2d` return the exact ZOH form
`A = [[I, dt·I],[0, I]]`, `B = [[dt²/2·I],[dt·I]]`, so the tube RPI set is exact rather than approximate.

`barrier_expression()` — `h_j(x) = (px − ox)² + (py − oy)² − (r_j + inflation)²`. For
`quadrotor_planar` use `(px, pz)`. This expression and `MpcCbfSolver::barrierValue` must agree to
`1e-9`; the gtest `BarrierMatchesGeneratedCode` enforces it.

`dcbf_constraint(h_next, h_now, gamma, omega=None)` — returns `h_next − h_now + (omega or 1) * gamma * h_now`,
which the OCP constrains to be `≥ 0`.

### §2.3 Parameter vector layout — fix this once, mirror it everywhere

The generated solver's per-stage parameter vector `p` is:

```
index                  contents
0 .. 7·n_obs−1         per obstacle j: [ox, oy, oz, vx, vy, vz, radius]     (7 doubles each)
7·n_obs                gamma
                       [tube solver only:]
7·n_obs+1 .. +n_obs    tightening c_j for this stage                        (n_obs doubles)
```

Obstacle positions are pushed **already propagated to the stage**: for stage `k`,
`o_j(k) = o_j(0) + k · dt · v_j` when `is_dynamic`, else `o_j(0)`. The velocity entries are carried in
the parameter vector anyway, for diagnostics and future use.

With `n_obs = 8`: `np = 57` (nominal), `np = 65` (tube). Put these numbers in a comment at the top of the
generated-model builder and in `MpcCbfSolver::Impl`.

### §2.4 `generate_mpc_cbf_solver.py`

`build_acados_model()`:
- `model.x`, `model.u`, `model.p` per §2.2/§2.3.
- **`model.disc_dyn_expr = discretise(...)`** and `ocp.solver_options.integrator_type = 'DISCRETE'`.
  Do not use `ERK`/`IRK` — this is a discrete-time formulation and a continuous integrator changes what
  the CBF condition means.
- `model.name = f"mpc_cbf_{model_key}_N{horizon}_{variant}"`. The C++ side selects the generated solver
  by this string.

`build_ocp()`:
- Cost: `NONLINEAR_LS`, `y = vertcat(x, u)`, `y_e = x`, `W = blkdiag(diag(Q), diag(R))`, `W_e = diag(Qf)`.
- Bounds: `lbu/ubu/idxbu` for all inputs; `lbx/ubx/idxbx` for the finite state bounds only (skip entries
  set to ±1e9 in YAML).
- Constraints `con_h_expr` (stages `1..N−1`) and `con_h_expr_e` (stage `N`), stacking per obstacle:
  1. `h_j(x_k)` with `lh = 0`, `uh = 1e9`
  2. `h_j(f(x_k,u_k)) − h_j(x_k) + γ h_j(x_k)` with `lh = 0`, `uh = 1e9`, for `k < N_CBF`
  Row order matters: **obstacle-major within each row type**, and the same order is assumed by
  `SolverDiagnostics::cbf_values` (index `k · n_obs + j`). Write the layout in a comment in both places.
- Stage 0: the initial state is fixed, so the `h(x_0) ≥ 0` row is a constant — emit it anyway (it makes
  an unsafe initial state show up as infeasible, which is the behaviour `InfeasibilityReasonIsPopulated`
  tests) but expect acados to report it immediately.
- `variant == "relaxed_decay"`: extend `u` by `n_obs` slack-like variables `ω_j`, bound them by
  `[omega_min, omega_max]`, add `omega_weight · (ω_j − 1)²` to the LS cost by appending
  `sqrt(omega_weight) · (ω − 1)` rows to `y`, and use the `ω` form of the DCBF expression.
- `variant == "distance_only"`: emit only row type 1.
- Solver options: `qp_solver='PARTIAL_CONDENSING_HPIPM'`, `hessian_approx='GAUSS_NEWTON'`,
  `nlp_solver_type='SQP'` (or `'SQP_RTI'` with `--rti`), `levenberg_marquardt=1e-4`,
  `nlp_solver_max_iter=max_sqp_iterations`, `qp_solver_warm_start=1`, `print_level=0`.

`generate_all()` must emit exactly this matrix (CI depends on it):

| model | N | variant | consumed by |
|---|---|---|---|
| `double_integrator_2d` | 8 | `fixed_decay` | `2d_obstacle.launch.py`, gtests, ACC notebook |
| `double_integrator_2d` | 3 | `distance_only` | MPC-DC baseline |

### §2.5 `generate_tube_solver.py`

Import from `generate_mpc_cbf_solver` rather than copying. Three differences only:

1. Variables named `(z, v)`; bounds arrive **already tightened** from the caller — this script must not
   compute them (the C++ `initialize()` is the single source of truth).
2. Parameter vector extended per §2.3.
3. Barrier rows become `h_j(z_k) − c_{j,k}` and `h_j(F(z_k,v_k)) − h_j(z_k) + γ(h_j(z_k) − c_{j,k})`.

`compute_offline_sets()` is the **Python reference implementation** of the LQR + mRPI computation. Its
only job is to cross-check the C++: the gtest asserts the two agree on `Ω`'s support function in 32
directions to `1e-6`. Use `scipy.linalg.solve_discrete_are` here so the two implementations are genuinely
independent (the C++ side iterates the Riccati recursion).

## §3. `MpcCbfSolver` (`src/mpc_cbf_solver.cpp`)

### §3.1 Structure

Everything acados-specific lives in `MpcCbfSolver::Impl` inside the `.cpp`. The header must remain
compilable without acados on the include path — that is why the pimpl exists; keep it that way.

Guard all acados code with `#if MPC_CBF_WITH_ACADOS` (CMake defines it when `ACADOS_SOURCE_DIR` is set).
In the `#else` branch, `initialize()` returns `false` and `solve()` returns `kNotInitialized`. Never fake
a solution.

### §3.2 Dimensions

`stateDimOf`: 4 / 3 / 4 / 6. `inputDimOf`: 2 for all four. Under `relaxed_decay` the *generated* input
dimension is `nu + n_obs`, but `inputDim()` and `MpcCbfSolution::u0` expose only the physical `nu`.
Keep `ω` in `SolverDiagnostics::omega`, not in `u0`.

### §3.3 `initialize()` — validation list

Reject (return `false`, log the offending field to `stderr` with the value) when any of:

```
gamma ∉ (0, 1]                          horizon < 1                    dt <= 0
Q.size() != nx  |  R.size() != nu  |  Qf.size() != nx
x_min.size() != nx | x_max.size() != nx | u_min.size() != nu | u_max.size() != nu
any(u_min > u_max)  |  any(x_min > x_max)
any non-finite entry in any bound or weight
variant == kRelaxedDecay and (omega_min < 0 or omega_max*gamma > 1 + 1e-9 or omega_min > omega_max)
max_sqp_iterations < 1                  kkt_tolerance <= 0
```

Then: clamp `cbf_horizon` to `[1, horizon]` (`<= 0` means `horizon`), allocate the acados capsule, push
cost matrices and bounds, size every buffer. **After `initialize()` returns, `solve()` must not allocate**
— `SolveDoesNotAllocate` checks this.

### §3.4 `barrierValue()`

```cpp
// h(x) = ||p(x) - p_obs||^2 - (r_obs + inflation_radius)^2
```
`p(x)` uses the position indices from §2.2 (`(px, pz)` for the planar quadrotor). Positive = safe. No
square roots — the squared form is what the generated code enforces, and mixing the two makes every
diagnostic wrong by a nonlinear factor.

### §3.5 `solve()` — step by step

```
1  guards      !initialized                       -> kNotInitialized
               x0.size() != nx or !x0.allFinite() -> kNanDetected, reason set, no acados call
2  obstacles   sort by ||p(x0) - o_j||, keep nearest kMaxObstacles (§3.6),
               pad unused slots with {position = (1e6,1e6,1e6), radius = 0, is_dynamic = false}
3  parameters  for k = 0..N: build the stage parameter vector per §2.3 into the pre-sized
               buffer; ocp_nlp_in_set(..., k, "p", buf)   [verify the API name for your version:
               some releases use <name>_acados_update_params(capsule, k, p, np)]
4  reference   set "yref" per stage from x_ref (and zeros for the u block), "yref_e" at stage N
5  initial     ocp_nlp_constraints_model_set(..., 0, "lbx", x0) and "ubx"
6  warm start  if a guess exists, ocp_nlp_out_set(..., k, "x"/"u", ...)
7  solve       t0 = steady_clock::now(); status = <name>_acados_solve(capsule); measure
8  read back   ocp_nlp_out_get(..., k, "x"/"u", ...) into x_pred / u_pred
9  diagnostics §3.7
10 status      map acados return codes: 0 -> kSuccess, 1 -> kNanDetected, 2 -> kMaxIterations,
               3 -> kQpFailure, 4 -> kInfeasible (QP), other -> kQpFailure.
               VERIFY these against acados_solver_common.h in your version — do not trust this table
               blindly, and put the verified mapping in a comment.
11 warm start  store x_pred/u_pred shifted one stage (append the last column twice) for next time
```

### §3.6 Obstacle pruning

`kMaxObstacles = 8` is compiled into the generated solver. Sorting by current distance is adequate for
the demos but is *wrong in general* for fast obstacles approaching from behind. Implement the distance
sort, and add a one-line comment recording that limitation — do not silently pretend it is optimal.

### §3.7 Diagnostics

Fill on **every** solve, success or not:

- `cbf_values[k*n_obs + j] = barrierValue(model, x_pred.col(k), obstacle_j_at_stage_k, inflation)`
- `cbf_slack` — the DCBF row residual `h_{k+1} − h_k + γ h_k` (≥ 0 means satisfied)
- `omega` — read from the generated input vector's tail under `kRelaxedDecay`, else empty
- `first_active_cbf_step` / `first_active_obstacle` — the `(k, j)` minimising `cbf_slack`, reported only
  when that minimum is below `1e-3` (call it `kActiveTolerance`, a named constant); `-1` otherwise
- `solve_time_ms`, `sqp_iterations` (`ocp_nlp_get(..., "sqp_iter")`), `kkt_residual`
  (`ocp_nlp_get(..., "residuals")` — take the max), `cost` (`ocp_nlp_get_cost_value` or equivalent)

`infeasibility_reason` — build a specific string, not a generic one. Classify in this order:

```
x0 non-finite                       -> "non-finite state: <index>"
h_j(x0) < 0 for some j              -> "initial state violates barrier for obstacle <j> (h = <v>)"
u bounds inconsistent               -> "input bounds infeasible"
QP reported infeasible              -> "QP infeasible; tightest DCBF row at stage <k>, obstacle <j>, slack <s>"
max iterations                      -> "max SQP iterations (<n>), KKT residual <r>"
otherwise                           -> "solver returned <code>"
```

### §3.8 Enum conversion helpers

`toString` returns a static string literal (never a dangling pointer). `parseModelType`/`parseCbfVariant`
accept the YAML spellings case-insensitively and leave the output untouched on failure.

## §4. `TubeMpcCbfSolver`

### §4.1 What is shared

Reference handling, obstacle pruning and propagation, the diagnostics block, and the acados plumbing are
identical to §3. Factor the shared parts into file-local helpers rather than duplicating them.

### §4.2 What is different

Decision variables are nominal `(z, v)`; the applied input includes the ancillary term; the barrier rows
carry the tightening; the bounds are tightened.

### §4.3 `initialize()` — order matters

```
1  validate the MPC/CBF configs exactly as §3.3
2  (A, B)      exact ZOH for double_integrator_2d; otherwise linearise about the current reference and
               log at WARN that the certificate is local to that point
3  K           compute_gain_from_lqr ? discreteLqrGain(A,B,diag(lqr_Q),diag(lqr_R)) : tube.K
               reject if spectralRadius(A + B K) >= 1 - 1e-9
4  Omega       computeRpiSet(A + B K, W, rpi_epsilon, rpi_max_iterations); reject if !converged
5  tightening  tightened_x = X ⊖ Omega;  tightened_u = U ⊖ (K Omega)
               reject if either isEmpty() -> "disturbance set too large for the input bounds"
6  verify      verifyInvariance(); reject on failure
7  log         alpha, iteration count s, Omega's bounding box, ||K||, at INFO
8  allocate    the acados tube solver with the tightened bounds
```

Steps 3-6 are the entire robustness argument. Failing at startup is correct behaviour; a runtime
infeasibility caused by an oversized `W` is not.

### §4.4 `tighteningFor()`

```
kSupportFunction:  grad = 2 * Pᵀ (P z − p_obs)  (lifted to R^nx, zeros on non-position states)
                   c    = Omega.support(−grad)
kLipschitz:        c    = lipschitz_h * Omega.maxNorm()
kNone:             c    = 0
```

Per §1.5, the dropped `‖Pe‖²` term is non-positive, so the support-only margin is an over-estimate and
therefore **sound**. Do not add the quadratic term back with a positive sign.

`c ≥ 0` always (because `0 ∈ Ω` implies `h_Ω(d) ≥ 0`). Assert it.

### §4.5 `solve()` — the `z_0` policy

```
first solve, or  (x0 − z_prev(:,1)) ∉ Omega   ->  z_0 = x0     (reset the tube)
otherwise                                     ->  z_0 = z_prev(:,1)   (shifted nominal)
```

Anchoring `z_0` to the shifted nominal state is what makes the tube argument hold across steps; setting
`z_0 = x0` every step throws the guarantee away and quietly degrades to nominal MPC. Log at DEBUG each
time the tube resets.

Then: push `c_{j,k}` per stage, solve, and

```
u_applied = clip(v_0 + K (x0 − z_0), u_min, u_max)
```

Count clip events. A correct tightening means the clip never triggers (`AncillaryInputRespectsBounds`);
if it does, the tightened input set was computed wrongly, so surface it in diagnostics rather than
absorbing it.

## §5. Convex sets (`disturbance_sets.hpp` implementations)

Implemented in `tube_mpc_cbf_solver.cpp` for now (split out past ~600 lines).

### §5.1 LP backend

`Polytope::support`, `isEmpty` and `removeRedundantHalfspaces` all need an LP. Write **one** dense
simplex/Big-M routine in an anonymous namespace (~120 lines) and route everything through it. Do not add
an external LP dependency for problem sizes this small, and do not write three ad-hoc solvers.

Sizes here are tiny (`n ≤ 6`, rows ≤ a few hundred). Prefer clarity and numerical care (explicit
tolerances, no `1/x` without a guard) over speed.

### §5.2 Exactness table — keep it honest

| Operation | Polytope | Zonotope |
|---|---|---|
| support | exact (LP) | exact (closed form `dᵀc + ‖Gᵀd‖₁`) |
| Minkowski sum | **outer approximation** (support in the union of both normal sets) | exact (concatenate generators) |
| Pontryagin difference | exact (`b_i ← b_i − h_Q(a_i)`) | n/a |
| linear map | exact if invertible, else via vertices (n ≤ 3) | exact |
| order reduction | n/a | **outer approximation** (Girard) |

Every approximation must be an **over**-approximation. An under-approximation anywhere here silently
breaks safety downstream, which is why `OrderReductionOverApproximates` samples and checks containment.

### §5.3 `computeRpiSet()` — Raković et al.

```
if spectralRadius(A_cl) >= 1: return {converged = false}
for s = 1 .. max_iterations:
    alpha_s = max over the sampled/normal directions a of  h_W(A_cl^{sᵀ} a) / h_W(a)
    if alpha_s >= 1: continue
    M(s)   = max over axes i of  Σ_{j=0}^{s-1} [ h_W(A_cl^{jᵀ} e_i) + h_W(−A_cl^{jᵀ} e_i) ]
    if alpha_s / (1 − alpha_s) * M(s) <= epsilon: break
F_s   = ⊕_{j=0}^{s-1} A_cl^j W          (zonotope; reduceOrder every few steps)
Omega = F_s scaled by 1/(1 − alpha)
```

Analytic reference for the test: `A_cl = λI`, `W = box(w)` gives `Ω = box(w/(1−λ))`. `RpiTest` checks
against it.

### §5.4 `discreteLqrGain()`

Iterate `P ← Q + AᵀPA − AᵀPB (R + BᵀPB)⁻¹ BᵀPA` to a fixed point, then `K = −(R + BᵀPB)⁻¹ BᵀPA`.
**Sign convention: the returned `K` makes `A + BK` Schur** (note the minus in the formula). Use
`Eigen::LLT` for the inverse and fail loudly if `R + BᵀPB` is not positive definite.

## §6. ROS 2 node (`src/mpc_cbf_node.cpp`)

### §6.1 Lifecycle

Constructor: `declareParameters()` → `loadParameters()` → `setupSolver()` → `setupInterfaces()`.
On failure in either middle step: log `FATAL` with the reason and `rclcpp::shutdown()`. A controller that
starts with a silently-substituted configuration is worse than one that refuses to start.

### §6.2 Parameters

Every key in `config/mpc_cbf_params.yaml` and `config/tube_mpc_params.yaml`, declared with a
`ParameterDescriptor` carrying a description and a range where meaningful (`gamma` in `(0,1]`,
`control_rate_hz > 0`).

Read-only (require a restart / different generated solver): `model`, `horizon`, `dt`, `cbf_variant`,
`use_tube_mpc`, and everything under `tube:`.
Live-changeable via an `add_on_set_parameters_callback`: `gamma`, `Q`/`R`/`Qf`, `safety_margin`,
`ego_radius`, `infeasible_policy`. Reject everything else in the callback with a clear reason string.

### §6.3 Control loop

```
1  copy shared state under state_mutex_, release the lock before solving
2  if (now − last_odom_stamp_) > odom_timeout_s:
       publish the fallback input, DiagnosticStatus ERROR "odometry stale (<age> s)", return
3  solve
4  if !solution.usable(): handleSolverFailure(solution); return
5  publish cmd, predicted path, cbf values, diagnostics; consecutive_failures_ = 0
```

Put the timer in its own `MutuallyExclusive` callback group so a slow solve cannot re-enter itself.

### §6.4 Failure policy

`infeasible_policy` ∈ `{hold_last, zero, brake, previous_horizon}`:

| policy | behaviour |
|---|---|
| `hold_last` | republish the previous input |
| `zero` | publish zeros |
| `brake` | publish the maximum-deceleration input admissible under `u_min`/`u_max` |
| `previous_horizon` | apply `u_pred.col(1)` from the last successful solve, advancing an index each failure; falls back to `brake` when the stored horizon runs out |

`previous_horizon` is the default because it is the only one with any relationship to the constraints —
say exactly that in the code comment, and be aware none of the four is a guarantee (§1.4).

Diagnostics: `WARN` on the first failure, `ERROR` from `max_consecutive_failures` onward, always carrying
`infeasibility_reason` and `first_active_cbf_step` as key/value pairs.

### §6.5 Frames — a real source of bugs

`nav_msgs/Odometry` carries **body-frame** twist and **odom-frame** pose. For
`kDoubleIntegrator2D` the state's `(vx, vy)` are world-frame, so rotate the twist by the pose yaw. Write
the rotation explicitly and add a comment; getting this wrong produces a controller that works in
simulation with zero initial yaw and fails on hardware.

### §6.6 Missing plant nodes

The launch files reference simulator scripts that do not exist yet. Create them under
`mpc_cbf_unified/scripts/` and install them from `CMakeLists.txt`:

- `sim_double_integrator.py` — integrates the plant at `1/dt`, publishes `Odometry`, optional bounded
  disturbance (`--disturbance uniform|worst_case|gust`, `--w-max`, `--seed`)
- `sim_bicycle.py` — bicycle plant + lead-vehicle marker
- `sim_quadrotor_planar.py` — planar quadrotor plant + moving obstacle marker
- `track_reference.py` — centre-line reference publisher for the racing scenario
- `log_min_barrier.py` — records `min_k h(x_k)` per run to CSV for the sweep notebook

These are test fixtures, not products: keep them small, deterministic under a seed, and free of hidden
smoothing that would flatter the controller.

## Appendix A — pitfalls specific to this problem

1. **`ERK` instead of `DISCRETE` integrator.** Changes what the CBF condition constrains. §2.4.
2. **Barrier drift.** `barrierValue()` in C++ and `barrier_expression()` in Python must be identical.
   The gtest exists because this *will* drift otherwise.
3. **`γ > 1`.** Looks like "less conservative", actually voids invariance. §1.1.
4. **`ω_max · γ > 1`.** Same failure, one level less obvious. §1.3.
5. **LQR sign.** `K` such that `A + BK` is Schur, not `A − BK`. §5.4.
6. **Under-approximating set operations.** Every approximation must be outer. §5.2.
7. **`z_0 = x0` every step.** Silently degrades the tube to nominal MPC. §4.5.
8. **Body vs world frame twist.** §6.5.
9. **Claiming recursive feasibility.** It is not implemented and not guaranteed. §1.4.
10. **Allocation in `solve()`.** Breaks the real-time claim the header makes. §3.3.
