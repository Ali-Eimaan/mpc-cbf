# §3 · Build system

**Governs:** `mpc_cbf_unified/CMakeLists.txt`, `mpc_cbf_unified/package.xml`, `.gitignore`
**Milestone:** throughout — this is the file you touch at every milestone, not one you finish
**Done when:** A1 is green.

Both build files are **already complete** in the skeleton. Unlike the sources, they contain no
`TODO(deepseek …)`. Your job here is to keep them correct as targets appear, and to wire in the
generated acados sources at M2.

---

## §3.1 Target layout

| Target | Contains | Depends on |
| --- | --- | --- |
| `mpc_cbf_unified` (library) | `mpc_cbf_solver.cpp`, `tube_mpc_cbf_solver.cpp` (which also hosts the set arithmetic) | Eigen, acados — **rclcpp only for the logging macros** |
| `mpc_cbf_node` (executable) | `mpc_cbf_node.cpp` | the library + messages + tf2 |

**Keep the solver library free of ROS message and node dependencies.** It currently links
`rclcpp` for logging only. That split is what lets the unit tests run without a ROS graph, lets
the parity harness run standalone, and lets `transition-viable-swarm` link the solver without
pulling in a node. If you find yourself including `nav_msgs` or `rclcpp/node.hpp` in the library,
move that code into the node instead.

If you would rather have a hard split, replacing the logging macros with a small callback and
dropping `rclcpp` from the library is a welcome change — say so in the commit message and update
this table.

**When `tube_mpc_cbf_solver.cpp` exceeds ~600 lines, split the set arithmetic into
`src/disturbance_sets.cpp`** and add it to the library sources. The header already stands alone;
only the `.cpp` is shared, and only to keep M6 in one translation unit while it is being written.

## §3.2 acados discovery — the contract

acados is located through the `ACADOS_SOURCE_DIR` environment variable, set by acados' own
`env.sh`. The skeleton's logic:

```cmake
set(ACADOS_ROOT $ENV{ACADOS_SOURCE_DIR})
if(ACADOS_ROOT)
  set(MPC_CBF_WITH_ACADOS TRUE)   # -> target_compile_definitions(... MPC_CBF_WITH_ACADOS=1)
else()
  message(WARNING "... building solvers as stubs ...")
endif()
```

**Without acados the package still builds, and every solver reports
`SolverStatus::kNotInitialized`.** This is deliberate and MUST be preserved:

- it keeps `colcon build` green on a machine without acados, so the ROS layer and the tests can
  be compiled and reviewed anywhere;
- it makes the absence *loud*. A stub that returned a plausible `u0` would be the single most
  dangerous thing in this repository.

Never add a fallback QP, a "simple" unconstrained solution, or a zero-input default inside the
solver. The node's `infeasible_policy` ([09_NODE.md §9.4](09_NODE.md)) is the only place a
fallback control is chosen, and it is chosen with the failure visible in diagnostics.

## §3.3 Wiring in the generated code — do this at M2

After `codegen/generate_mpc_cbf_solver.py --all` has run, the generated C sources must join the
library. Replace the commented block in `CMakeLists.txt` with:

```cmake
set(ACADOS_GENERATED_DIR ${CMAKE_CURRENT_SOURCE_DIR}/../codegen/c_generated_code)
file(GLOB_RECURSE ACADOS_GENERATED_SOURCES ${ACADOS_GENERATED_DIR}/*.c)
target_sources(${PROJECT_NAME} PRIVATE ${ACADOS_GENERATED_SOURCES})
target_include_directories(${PROJECT_NAME} PRIVATE ${ACADOS_GENERATED_DIR})
```

Three warnings, each of which has cost someone a day:

1. **A `file(GLOB)` does not re-run when files appear.** After regenerating, re-run CMake
   (`colcon build --cmake-force-configure`) or the new solver silently is not compiled. If this
   bites more than once, switch to an explicit list generated by the codegen script.
2. **Generated code will not survive `-Wconversion`.** Wrap the generated include directory with
   `SYSTEM`, or set `-w` on those sources specifically. Do **not** drop the warning flags for the
   whole target — they are there to catch your `int`/`Eigen::Index` narrowing, not acados'.
3. **The generated sources are configuration-specific.** Building all six configurations from
   [05_CODEGEN.md §5.6](05_CODEGEN.md) into one library is intended; each has a distinct solver
   name, so their symbols do not collide. If they do collide, the `model.name` scheme was not
   followed.

## §3.4 Dependency linkage

`ament_target_dependencies` is deprecated from Kilted onward (§2.5, risk V6). Use namespaced
targets and `${pkg_TARGETS}`:

```cmake
target_link_libraries(mpc_cbf_node PRIVATE
  ${PROJECT_NAME}
  rclcpp::rclcpp
  tf2::tf2
  tf2_ros::tf2_ros
  ${std_msgs_TARGETS}
  ${geometry_msgs_TARGETS}
  ${nav_msgs_TARGETS}
  ${sensor_msgs_TARGETS}
  ${visualization_msgs_TARGETS}
  ${diagnostic_msgs_TARGETS}
)
```

The skeleton still uses `ament_target_dependencies` in places. **Migrate it when you first touch
the file**, and if a namespaced target name does not exist on `lyrical`, find the correct one and
fix it here — do not silently revert.

## §3.5 Warnings

```cmake
add_compile_options(-Wall -Wextra -Wpedantic -Wshadow -Wconversion)
```

`-Wconversion` is on deliberately. In numerical code it catches the `int`/`Eigen::Index` and
`float`/`double` narrowing that silently loses precision when indexing a horizon or a parameter
buffer. **Fix the warnings; do not remove the flag.** Expect noise from Eigen expression
templates — if a warning is genuinely Eigen's and not yours, suppress it narrowly with
`#pragma GCC diagnostic push/pop` around the specific line, never globally. Generated acados code
is the documented exception (§3.3).

Consider adding `MPC_CBF_ENABLE_NATIVE_ARCH` (default OFF) for `-march=native` when benchmarking
locally; never for a distributed binary, and never in CI — it makes A2 irreproducible across
machines.

## §3.6 `package.xml`

Format 3. Points to watch:

- `<license>BSD-3-Clause</license>` must match `LICENSE` (§2.6).
- `<depend>eigen</depend>` is the rosdep key for `libeigen3-dev`, not a CMake target name.
- There is no rosdep key for acados. It is built from source (§2.2) and the workflow must not
  expect rosdep to supply it.
- Version stays `0.1.0` until the release gate in [15_ROADMAP.md §18](15_ROADMAP.md) is met.

## §3.7 Script installation

The rclpy simulator nodes live in `mpc_cbf_unified/scripts/` ([09_NODE.md §9.6](09_NODE.md)) and
must be installed for `ros2 run` and the launch files to find them:

```cmake
install(PROGRAMS
  scripts/sim_double_integrator.py
  scripts/sim_bicycle.py
  scripts/sim_quadrotor_planar.py
  scripts/track_reference.py
  scripts/log_min_barrier.py
  DESTINATION lib/${PROJECT_NAME})
```

Add this block at M8. Forgetting it produces a launch failure that names the executable but not
the cause.

## §3.8 Test registration

Every gtest is registered with `ament_add_gtest` and linked against the library only. **A test
that needs rclcpp does not belong in that set** — the point of the split in §3.1 is that the
suite runs without a ROS graph.

Adding a test file means adding its `ament_add_gtest` block. Forgetting this is silent: the file
compiles nowhere and CI stays green. Check the test count in `colcon test-result` when you add
one.

`test_recursive_feasibility.py` is registered through `ament_add_pytest_test` with a 600 s
timeout; it sweeps hundreds of solves and will exceed a default timeout on a slow runner.

At M5 you will add `cpp_solve_cli` ([11_PYTHON_REFERENCE.md §11.5](11_PYTHON_REFERENCE.md)) as a
test-only executable:

```cmake
add_executable(cpp_solve_cli test/cpp_solve_cli.cpp)
target_link_libraries(cpp_solve_cli PRIVATE ${PROJECT_NAME})
```

It must be discoverable by the pytest run — install it to the package `lib/` directory or pass
its path through an environment variable set in `ament_add_pytest_test`. Pick one, and document
it in the test file's docstring.
